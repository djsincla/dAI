What each document is for, and how much to trust it

Documents here are one of four kinds, and mixing them up is how a repository ends up with a specification nobody believes. Each entry says which it is and when it was last true.

Kinds

Read this first

reference
Describes what is built and running. If it disagrees with the code, the document is wrong and should be fixed.
decision
Why something is the way it is, with the measurement or failure that settled it. Still true even when the code moves on - superseded decisions get an entry saying what replaced them.
findings
A measurement taken on a date. Not maintained: it says what was true when it was run, and the date is part of the claim.
plan
Something intended. The parts that have been built say so; the rest is not a description of the system.

Also

Outside this directory

  • The capabilities page - what the system can do, with every figure a measurement, and unproven things marked as unproven in the same table as the proven ones. A capabilities page that only lists successes is advertising.
  • examples/python/ - five scripts against the serving gateway and a RAG index over California's Lanterman Act, including one that answers through a group's socket using a model split across two machines.
  • spike/*/FINDINGS.md - the Phase 0 measurements the design is grounded in. Where a choice exists only because a measurement forced it, the decision record cites the spike.
If a reference document disagrees with the code, the document is wrong. If a decision looks arbitrary, it is probably load-bearing - the entry says what it cost to learn.
