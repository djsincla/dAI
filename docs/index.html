dAI - distributed AI on harvested Apple Silicon

Studio Macs sit idle sixteen hours a day. This schedules that capacity for AI work without anyone noticing, and without a byte leaving the building.

The argument

Sovereignty and sunk cost, not price-performance. Per token, harvested Macs lose to both cloud APIs and rented GPUs, and that argument is unwinnable. The two that hold: the marginal cost is electricity on hardware already bought, and the data never leaves the premises.

The model is the second-GPU render farm, with one difference that decides the whole design. That worked because of physical isolation - a card the artist's session could not touch. Apple Silicon shares one memory pool and one bandwidth budget, so isolation here is policy, not hardware. It is a weaker guarantee, and it means the social problem is the real one: one person noticing their machine got slow ends the programme.

What the machine will and will not do

Measured, not chosen. Every configuration tested was perceptible to a user present at the machine, so GPU work is confined to states where nobody is there. The Neural Engine is separate silicon and measured indistinguishable from no load, which is why three of the five states permit it.

How a node is trusted

Identity in hardware

The node's key is generated inside the Secure Enclave and never exists outside it. What is on disk is 284 bytes sealed to that machine: copied elsewhere it is inert, so a certificate taken from a stolen laptop names a key the thief cannot use.

Signed, not asserted

A join token gets a machine into a queue and nothing more. An admin approves it, and only then is a certificate issued - client-auth only, EC P-256, short-lived, so a stolen machine stops being a fleet member on its own.

One machine, one node

Enrollment is tied to the hardware UUID, so a reinstalled machine replaces its old record instead of appearing twice and having its capacity counted twice.

Least privilege

The daemon runs as a service account with no shell and no password, not as root. It needs no entitlement, which is a consequence of reaching the Enclave through CryptoKit rather than the keychain.

The person whose machine it is

Isolation here is policy, so the only hard guarantee a machine's owner has is that the off switch works. It is a file, not a request: it works with the control plane unreachable and needs no privilege, because requiring sudo to stop a background process on your own machine is the same as having no button.

No administrator can lift it. The fleet view shows "paused by owner" and offers no control, because a button that must either lie or fail is worse than a plain statement that this is not yours to lift. A menu bar app shows what is running, why, and what the machine has contributed.
