What the fleet says when it says no

Every refusal this system produces, what it actually means, and what to do about it. Organised by the message you are looking at, because that is what you have when something is wrong.

1 A request was refused 2 A machine is not taking work 3 A machine cannot talk to the control plane 4 A split will not run 5 Nothing is wrong and nothing is happening 6 Where to look

1

A request was refused

All of these are 503 with a code. On the OpenAI surface it is error.code; on the Anthropic surface, whose error shape has no such field, it is error.dai.code.

CodeMeansDo
no-nodes No active node is holding the reverse channel. Check the machines are up and approved. If they are heartbeating but not serving, their agent is reconnecting - look at the node log.
all-in-use Every node has a user present, so GPU work is not permitted. Nothing. This is the product working. It resolves when somebody locks their screen.
no-capacity-for-kind No node can run this kind of work at all. Usually a machine with no GPU model configured being asked to generate.
not-offered The model runs across machines and no cluster group is serving it. Assign it: PUT /pools/{id}/serving-model with confirm: true. Nothing is broken - what is missing is a decision.
gang-not-cluster A split needs cluster-tier machines and none connected is one. Give the machines the cluster tier, or accept that this model cannot run on harvest hardware - a split rank cannot be preempted.
gang-short The group cannot field the machines the model needs, or they have no way to reach each other. Two checks, in order: are all of them connected, and has each said where its peers should dial it (DAI_PIPELINE_INTERFACE)? A node whose link is down reports no address, and that is the honest state rather than a fault.
group-disabled You are talking to a group's socket and the group has been stood down. Bring it back with PUT /pools/{id}/enabled, or use another group's port. The listener stays bound on purpose: a refused connection would be indistinguishable from a control plane that had fallen over.
node-unreachable A gang formed and broke. The message names every rank and what each said. Read the ranks. The one that stayed silent is usually the machine that caused it.

2

A machine is not taking work

The node's own log says asked for embed, generate, got none: <reason>. These are the reasons.

ReasonMeans
emptyThere is no work. The fleet is idle.
none-of-these-kindsThere is work, but not of a kind this machine may run right now - almost always GPU work while somebody is at the keyboard.
no-poolThere is work, and this machine is in no group that can be given it.
node-pausedAn operator paused it. Liftable in the console.
user-pausedThe machine's owner paused it. Not liftable by anyone else, deliberately.
holding-a-splitThis machine's cluster group is serving a model that runs across machines, so it is not available to its harvest group. It returns on its own when the group stops serving that model - there is nothing to lift.
Why holding-a-split is not no-pool

The machine is in that harvest group. An operator sent to look at membership would find nothing wrong and no explanation, which is why the two are reported separately.

3

A machine cannot talk to the control plane

MessageMeansDo
no client certificate The request arrived without one. Usually something other than an agent talking to the agent surface.
unknown certificate The fingerprint is not in the fleet. If it follows a renewal, a loop in the daemon is still presenting the old certificate - restart the daemon and report it, because that is a bug and has happened twice.
node not approved Enrolled and waiting. Approve it in the console.
superseded The machine re-enrolled and this is the older identity. It verifies perfectly, which is exactly why it is refused. Re-enrol, or point the daemon at the current identity.
certificate revoked Withdrawn deliberately.Re-enrol if that was not intended.
certificate expired; re-enroll Past thirty days with no renewal. Re-enrol. An expired certificate cannot authenticate, so the machine cannot be asked to renew - the console will not offer the control.
node cordoned Held out of the fleet by an operator.Uncordon it.

4

A split will not run

Read both machines' logs. The link says what happened to it, and the two halves usually say different things.

# what a working split looks like, on both machines rank 0 listening on 7710 pipeline: a peer connected from 192.168.99.2 pipeline: handshake completed with 192.168.99.2 rank 0 (layers 24..<48) finished 205 tokens in 15.4s
What you seeWhat it is
no handshake with … after 10s TCP connected and TLS never proceeded. Almost always the peer going away mid-handshake - check it is still up and the link still has an address.
bind: Address already in use A previous split left its listener bound. Fixed in 2026.08.13-6; if you see it, the machine is running something older.
the other machine did not answer within 120s The ranks paired and one of them never produced its tensor. Usually a machine loading its half under heavy load.
rank N could not hand its hidden state on The link broke mid-generation. The other rank's message says from which end.
did not report before the gang was released This rank said nothing at all within two seconds of another rank failing. It is usually the machine that caused the failure.
The link is not the control plane's link

A split runs over whatever the machines share - a Thunderbolt bridge, say - while both talk to the control plane over the LAN. A bridge goes inactive when its peer sleeps or is unplugged, and then the address a node advertised stops being reachable. The node clears its address on the next heartbeat, and a gang with nowhere to dial is refused in milliseconds rather than attempted.

5

Nothing is wrong and nothing is happening

  • A machine reads as suspended. Its cluster group is serving a split model. That is the system working; the capacity is deliberately withdrawn.
  • A model is listed but every request is refused. The catalogue says a node holds it and can serve it; routing says no node is free this instant. A node reading a large prompt is occupied for minutes and is not parked on the channel.
  • A group shows "not serving this group's model". The machines are running something else - either they have not taken the group's model yet, or a cluster group is overriding this one. The card names which.
  • A node is not holding what it was assigned. The drawer shows the reason under "Not holding". It is reported on every beat, so it is current, not a stale error from hours ago.
  • Health says 503 with a group name. That group has a socket nothing is listening on - the dangerous case, because the group otherwise looks entirely healthy.

6

Where to look

# on a machine that lends capacity /var/log/dai/agent.log # both loops: heartbeats, work, serving, splits /var/log/dai/updater.log # self-update, every 120s # on the control plane /var/log/dai-control/ # when installed as a daemon GET /admin/v1/agent/upgrades # what each machine tried, and how it ended GET /monitor/v1/metrics # Prometheus exposition

The node drawer in the console carries the same facts a person would ssh for: chip, working set, headroom, presence, agent version and fingerprint, certificate expiry, why it is not holding something, and its recent activity - readable by that machine's owner whatever their role, because without it any unrelated slowdown gets blamed on the agent with no way to check.
