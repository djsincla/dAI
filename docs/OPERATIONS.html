Operations · running a fleet

Every gesture, what it costs, and how to undo it

Day-two operations: the things you do after the fleet exists. Each one says what it changes, what it takes away from somebody, and whether it can be reversed. Installation is a separate document.

1

Looking at the fleet

The console is the fleet view; everything below has an equivalent there. The API is shown because it is what a script uses and what an error message can be pasted into.

# sign in once; every call below uses $TOK $ TOK=$(curl -sk https://host:8452/admin/v1/auth/login \ -H 'content-type: application/json' \ -d '{"username":"admin","password":"..."}' | jq -r .token) $ curl -sk https://host:8452/admin/v1/nodes -H "authorization: Bearer $TOK" | jq $ curl -sk https://host:8452/admin/v1/pools -H "authorization: Bearer $TOK" | jq $ curl -sk https://host:8452/monitor/v1/health # from a permitted range

/monitor/v1/health answers 503 when a group has a socket that nothing is listening on, naming the group and the port. That is the failure it exists for: the group is there, its models are assigned, its machines are holding them, and nothing answers.

2

Machines

Approve a machine

A newly enrolled machine is pending and runs nothing until approved. Nothing happens on it before that, which is the point.

$ curl -sk -X POST https://host:8452/admin/v1/nodes/id/approve \ -H "authorization: Bearer $TOK" -d '{}'

Pause a machine, and who can

An operator's pause is administrative and liftable. The machine owner's pause is not - there is no admin control for it, and the console shows a disabled label rather than a button that would have to lie.

Change which tiers a machine offers

The Tiers view in the console. Dragging there changes what the box is willing to be, which is different from which group claims it.

Worth knowing

A machine that offers both tiers reads as cluster everywhere, including for the presence exemption when serving - so an interactive request can land on it while somebody is using it. If that matters for a particular workstation, give it only the harvest tier.

3

Groups

Create one

It is allocated a socket immediately, bound before the response is sent, and the port is in the response and on the group's card. Point applications at that port; nothing else selects a group.

$ curl -sk -X POST https://host:8452/admin/v1/pools \ -H "authorization: Bearer $TOK" -H 'content-type: application/json' \ -d '{"name":"split-cluster","tier":"cluster"}' {"id":"...","name":"split-cluster","tier":"cluster","servingPort":8461}

Creating a cluster group sets schedule = gang and preempt = never automatically. A cluster group admits only cluster-tier machines; a harvest group admits anyone, because a dedicated box is strictly more reliable than a harvested one.

Give an older group a socket

Groups made before sockets existed do not get one during an upgrade - binding listeners nobody asked for, on a machine nobody is watching, is how a control plane comes back holding ports somebody else wanted. Ask once:

$ curl -sk -X PUT https://host:8452/admin/v1/pools/id/socket \ -H "authorization: Bearer $TOK" {"servingPort":8460,"allocated":true}

Stand a group down, and bring it back

Reversible

A disabled group keeps its machines, model, socket and roles and asserts none of them: it decides nothing about what its machines serve, suspends nobody, hands out no work, forms no gangs, and refuses on its own socket with group-disabled. The response says which machines are affected and what each will serve now.

$ curl -sk -X PUT https://host:8452/admin/v1/pools/id/enabled \ -H "authorization: Bearer $TOK" -H 'content-type: application/json' \ -d '{"enabled":false}'

This is how you hand a cluster group's machines back to their harvest group for an evening without dismantling anything.

Delete a group

Not reversible

Its jobs and their work, its model assignments and every role on it go with it. Its machines are freed - membership lives on the group's own row, so there is nothing to tidy on them. Its socket is retired rather than reused, so a client left pointing at the old URL cannot quietly reach a different group.

$ curl -sk -X DELETE "https://host:8452/admin/v1/pools/id?confirm=true" \ -H "authorization: Bearer $TOK"

Without confirm=true it refuses and tells you exactly what would be lost. Read that before repeating the call.

4

Models

Push weights to a group

Declares that every machine in the group should hold these weights. Holding is not loading: a machine holds many models and serves one.

$ curl -sk -X PUT https://host:8452/admin/v1/pools/pool/models/model \ -H "authorization: Bearer $TOK" -d '{}'

Say what a group serves

This is the one that reaches the machines. Each node learns it on its next heartbeat and swaps its runtime - the old model's weights are released, and both loops on the machine take the same new runtime.

$ curl -sk -X PUT https://host:8452/admin/v1/pools/id/serving-model \ -H "authorization: Bearer $TOK" -H 'content-type: application/json' \ -d '{"modelId":"mlx-community/Qwen3-30B-A3B-Instruct-2507-4bit"}'

Setting it to null means nobody has said, which is not an instruction to unload: machines keep serving what they have.

Declare a model's shape

How many machines it runs across, and how much each needs. Checked at assignment, so a two-machine model assigned to a group with one is refused with a sentence rather than discovered at dispatch as a hang.

$ curl -sk -X PUT https://host:8452/admin/v1/models/id/shape \ -H "authorization: Bearer $TOK" -H 'content-type: application/json' \ -d '{"machines":2}'

5

Running a split

Four things must be true, and the fleet will tell you which one is not.

The model declares it needs more than one machine

PUT /models/{id}/shape {"machines": 2}. Otherwise it is routed as an ordinary model and answered by one machine.

A cluster group is serving it

PUT /pools/{id}/serving-model with confirm: true. The confirmation is not a formality: it names the machines that stop being available to their harvest group for as long as this stands.

The machines can reach each other

Each node says which of its interfaces its peers should use, with DAI_PIPELINE_INTERFACE in the agent's plist - the link a split runs over is deliberately not the one used to reach the control plane. A node whose link is down reports no address at all, and a gang with nowhere to dial is refused in milliseconds.

All of them are connected at once

A gang is admitted whole or not at all. A model that runs across every machine in its group leaves no spare rank, so any other request in flight - including a token count - blocks it for that moment.

# then ask, on the group's own socket $ curl -sk https://host:8461/v1/chat/completions \ -H "authorization: Bearer $TOK" -H 'content-type: application/json' \ -d '{"model":"...","max_tokens":40,"messages":[{"role":"user","content":"hello"}]}'

Both machines log their share: rank 0 (layers 24..<48) finished 205 tokens in 15.4s. The answer comes from rank 0, which holds the output head.

6

Agent versions

A pool is either managed - the control plane hands out the binary and machines self-update - or external, where it records what it expects and never acts, which is what makes it safe to run beside an MDM. Two systems racing to own one executable is worse than either owning it alone.

# register a build from a file on the control plane's disk $ curl -sk -X POST https://host:8452/admin/v1/agent/builds \ -H "authorization: Bearer $TOK" -H 'content-type: application/json' \ -d '{"version":"2026.08.13-7","path":"/path/to/dai-agent","notes":"..."}' # tell a pool which one to run $ curl -sk -X PUT https://host:8452/admin/v1/pools/id/agent \ -H "authorization: Bearer $TOK" -H 'content-type: application/json' \ -d '{"channel":"managed","version":"2026.08.13-7"}' # watch it converge - upToDate is compared by hash, not version string $ curl -sk https://host:8452/admin/v1/agent/rollout -H "authorization: Bearer $TOK" | jq

Machines pick it up within 120 seconds. The version a node reports comes from its plist and can stay stale after a self-update; the fingerprint is the hash of the running executable and is the thing to read.

7

Certificates

Certificates last thirty days and renew on their own at two thirds of life. You cannot renew one for a node: the key lives in the Secure Enclave and signs only inside that machine's daemon, so dai-agent renew over ssh fails even as root. You can ask.

$ curl -sk -X POST https://host:8452/admin/v1/nodes/id/renew \ -H "authorization: Bearer $TOK" {"hostname":"orca","asked":true}

The node acts on its next heartbeat and the request clears itself. The machine drawer shows the expiry, whether a request is outstanding, and offers the control only when it could work - an expired certificate cannot authenticate, so it can never be told to renew, and that machine needs re-enrolling instead.

Renewal is also how a machine acquires the node CA - the trust anchor for machine-to-machine links. A node enrolled before peer links existed cannot join a split until it renews.

8

Backup and restore

What the archive protects is disproportionate to its size: the CA private key is 1.7 KB, every node certificate traces to it, and enrolment needs the Secure Enclave - which will not generate a key over ssh. Losing it means walking to every machine in the building.

$ ./scripts/backup.sh /path/to/archives $ ./scripts/restore.sh /path/to/archive.tar.gz
Restore replaces the CA

Every certificate issued by the CA being discarded stops being trusted the moment it finishes. The old material is moved aside rather than overwritten, so a wrong archive is recoverable - but this is not a routine operation and it asks you to type the word.
