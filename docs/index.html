dAI: distributed AI on harvested Apple Silicon

Most of the Mac Studios I have looked after spend sixteen hours a day doing nothing in particular. dAI schedules AI work into that time, without the person at the desk noticing and without a byte leaving the building.

The argument

I should say up front that this does not win on price-performance. Per token, harvested Macs lose to the cloud APIs and to rented GPUs, and I have stopped arguing otherwise. Two things hold up: the marginal cost is electricity on hardware that has already been paid for, and the data never leaves the premises.

The model I had in mind was the render farm, where a second GPU sat in the artist's workstation and earned its keep overnight. That worked because the isolation was physical: the artist's session could not touch the card. Apple Silicon shares one memory pool and one bandwidth budget, so here isolation is policy, not hardware. It is a weaker guarantee, and it makes the social problem the real one. One person noticing their machine got slow is the end of the programme, and they tend not to keep it to themselves…

Interactive serving on harvested nodes is the trap everybody walks into first, so it is refused by design. A conversation needs the model still resident a minute from now, and a preemptible tier cannot promise that. It can promise to try, which is not the same thing.

How a node is trusted

Identity in hardware

The node's key is generated inside the Secure Enclave and never exists outside it. What sits on disk is 284 bytes sealed to that machine. Copied anywhere else it is inert, so a certificate lifted from a stolen laptop names a key the thief cannot use. Small comfort, given the laptop, but comfort.

Signed, not asserted

A join token gets a machine into a queue and nothing more. An admin approves it, and only then is a certificate issued: client-auth only, EC P-256 and short-lived, so a stolen machine stops being a fleet member on its own.

One machine, one node

Enrolment is tied to the hardware UUID, so a reinstalled machine replaces its old record instead of appearing twice and having its capacity counted twice.

Least privilege

The daemon runs as a service account with no shell and no password, not as root. It needs no entitlement, which is a consequence of reaching the Enclave through CryptoKit rather than the keychain.

The person whose machine it is

Because isolation here is policy, the only hard guarantee the owner of a machine gets is that the off switch works. It is a file, not a request. It works with the control plane unreachable and needs no privilege, because needing sudo to stop a background process on your own machine is the same as having no button.

No administrator can lift it. The fleet view shows "paused by owner" and offers no control, because a button that must either lie or fail is worse than saying plainly that this one is not yours to press. A menu bar app shows what is running, why, and what the machine has contributed.

One OpenAPI document is the source of truth for three independent implementations: the server, the Swift agent and the tests. A mismatch turns up between them rather than in production. Tool-call dialects are data, matched on a model's chat template rather than its name, so adopting a new model family is an edit and not a release.
