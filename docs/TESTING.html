What is proven, how, and what a test cannot reach

1,179 tests across two suites, a third that runs only under xcodebuild, and a set of claims that only real hardware can settle. This says which is which, because a suite that looks comprehensive and skips the hard parts is worse than one that admits its edges.

Running them

# control plane - 817 tests, ~3 min. Needs Postgres on 5433. $ cd control-plane && npm test $ npx tsc --noEmit # the suite does not typecheck; this does # agent - 362 tests, ~50s $ cd agent && swift test # the 15 that swift test skips, because SwiftPM cannot build MLX's shaders $ xcodebuild test -scheme dai-agent -destination 'platform=OS X' \ -derivedDataPath .xcbuild-test \ -only-testing:DaiAgentTests/PipelineBridgeTests \ -only-testing:DaiAgentTests/PipelineFaultTests \ -only-testing:DaiAgentTests/SyncBridgeTests \ -only-testing:DaiAgentTests/ServingModelTests \ -only-testing:DaiAgentTests/SplitUsageTests
Do not run two suites at once

Both vitest runs share one test database. A second one produces Hook timed out in 30000ms, which looks exactly like a real failure and is not.

scripts/release.sh runs both suites first and refuses to build if either fails. That is the whole reason it exists rather than being a line in a README: the two packages are built by separate scripts, and a release where one of them came from a tree that did not pass is a release nobody can reason about.

A fleet view that is confidently wrong is worse than no fleet view.

3

The tests that need Metal

SwiftPM cannot compile MLX's Metal shaders, so under swift test anything that creates an MLXArray aborts in C++ rather than throwing. Those tests are gated on the shader bundle being present and run under xcodebuild, which produces it.

The gate searches every loaded bundle rather than looking next to argv[0]: under xctest that is the runner, not the build products directory, so the obvious check skipped these tests everywhere - five tests that looked like coverage and had never executed once.

SuiteWhat it would have caught
PipelineBridgeTestsa tensor arriving with the wrong shape or element type, which feeds the second half of a model and produces a confident answer from the wrong numbers
PipelineFaultTestsa broken link killing the daemon; these run the shipped forward pass with a transport that refuses, and before the fix they took the test process down with them
SyncBridgeTeststhe transport called synchronously from inside an actor - the shape the model actually uses, and the one nothing else exercised
ServingModelTestsa machine failing to take up its group's model, or churning between models on every beat
SplitUsageTestsa split under-reporting its cost, or two ranks both reporting the prompt

4

What only hardware proves

Some claims cannot be held in place by a test at all, and pretending otherwise is how they rot. These are verified by running them on the fleet and reading the logs. The procedures are written out below rather than remembered, because every one of them was reconstructed from scratch at least once.

  • The Enclave key as a TLS server. The key cannot be created in a test process, so the socket tests use a file-based key pair. Whether a node can act as a TLS server with an Enclave key was only ever going to be answered on a machine.
  • A split answering. 48 layers divided 24/24, handshake in about a second, 205 tokens in 15.4s across two Macs.
  • Self-update convergence. Both machines taking a new build by fingerprint, including the case where the version string in the plist stays stale and only the hash tells the truth.
  • Certificate renewal. That the daemon can renew itself, that the node CA arrives with it, and that every loop starts presenting the new certificate.
  • Presence and sleep. What a Mac does when its owner walks away, which is not something a unit test has an opinion about.

Before any of them: is the fleet in a state worth testing?

export DAI_BASE_URL=https://localhost:8452
export DAI_CA_CERT="/Library/Application Support/dAI/server-ca.crt"
export DAI_ADMIN_USER=admin DAI_ADMIN_PASSWORD=...

python3 scripts/dai-split status     # ready / preparing / needs attention

Wait for ready. Every agent upgrade restarts both daemons and the shares rebuild - about 40 s each for the 32B. A test run against a preparing group measures the rebuild and reads as a fault.

A split answers

curl -sk https://localhost:8461/v1/chat/completions \
  -H "authorization: Bearer $DAI_API_KEY" -H 'content-type: application/json' \
  -d '{"model":"...Qwen2.5-Coder-32B-Instruct-4bit",
       "messages":[{"role":"user","content":"In one sentence, what is a hash map?"}],
       "max_tokens":40}'

The answer is the least of it. dai.split carries the layer ranges each machine held, and those are the actual evidence: two hostnames prove two machines were sent work, contiguous layer ranges prove neither held the whole model. Expect 3-11 tokens/s over Thunderbolt - a split is latency-bound at one hidden state per token, and single-machine decode of ~40 tokens/s is not the comparison.

The ordering that matters in the logs

pipeline: a peer connected from ...
pipeline: handshake completed with ...      <- must come BEFORE
rank 0 (layers 32..<64) finished N tokens

The listener used to hand its channel to runSplit when the TLS handlers went in rather than when the handshake completed, so rank 0 woke early and read a link still negotiating. It printed rank 0 failed one second before handshake completed. If that inversion ever reappears, this is the line that shows it.

Several conversations stay warm

Five requests, two conversations with no shared prefix, small max_tokens so prefill dominates rather than decode: A1, A2, B1, A3, B2. A3 is the test - with a single-entry cache, B evicted A and returning to A paid a full prefill. Measured on this fleet: cold 34.6 s, A3 0.8 s.

Two traps. A rank cannot serve two splits back to back - it has to re-park on the reverse channel first, and firing the next request immediately returns gang-short, which is the scheduler being right rather than a cache result; retry until the gang forms and time only the successful attempt. And the first request of a run may not be cold, because the cache survives client processes - use a genuinely unseen prompt for the cold baseline.

How long a prompt a split will take

Prefill carries the whole prompt's hidden state: tokens x hidden x width, which on the 32B at bfloat16 is 10,240 bytes per token. It used to travel as a single frame, so TensorCodec.maxPayload was a context ceiling on the link rather than the model - 64 MB, about 6,550 tokens - and a longer question tore the link down and reported a transport fault.

Tensors are now chunked, so a frame stays small (which is what bounds a single allocation from a length off the wire) and the tensor is reassembled up to maxTensorBytes, about 100,000 tokens. Worth re-testing with a genuinely long document; the unit tests carry the 121 MB hidden state that originally broke it.

Deploying an agent is not installing the package

POST /admin/v1/agent/builds   {"version":"X","path":"/path/to/binary"}
PUT  /admin/v1/pools/{id}/agent {"channel":"managed","version":"X"}   # every pool

com.dai.updater reconciles the binary against what the control plane names, on load and every 120 s. A plain installer -pkg is reverted within a second - updater.log said upgrading to 0.7.0 one second after a 0.8.0 install. Repoint every pool including stood-down ones, or re-enabling one drags the fleet back. The path is the binary, extracted from the package payload, and must be readable by _daictl.

The rule

When a hardware run finds something, the fix gets a test at whatever level can hold it - and where the failure was invisible, the test is usually an accessor added for the purpose. Both certificate handovers and the split's usage reporting are tested that way: not because the code is complicated, but because the failure was silent for hours.

5

How tests are written here

  • The name is the claim. "a request renews a certificate the clock would refuse", not "testRenew". A failing test should read as a sentence about the system.
  • The comment says what it cost to learn. Most tests here exist because something broke; the test carries the story so the next person does not delete it as redundant.
  • Exhaustive where the space is small. Layer division is checked for every count from 1 to 100 across 1 to 8 machines, because the failure mode - one layer owned by nobody - does not fail, it answers fluently from the wrong network.
  • Fakes implement the surface the loops actually use, not a tidier one. A mock of an imagined interface tests the imagination.
  • Tests bind real sockets where the thing under test is a socket, in their own port range so a control plane running on the same machine is not in the way.

6

Traps that cost an afternoon

A protocol extension can satisfy the requirement it was meant to call

When a conforming type's signature drifts, an extension with the same base name becomes the witness and recurses forever. Two fakes compiled happily while returning the wrong type. If a fake stops matching the protocol, check that the compiler is not quietly resolving to the extension.

A Task created inside an actor inherits its isolation

It then queues behind the very call it was meant to interrupt. The cancel watcher and the channel close are both Task.detached for this reason, and it is worth suspecting first whenever something never runs.

Foundation's waitUntilExit spins a run loop on the calling thread

Unusable from an actor across a suspension point. It hung swift test about one run in five, for an hour and fifty-four minutes on one occasion, and a stack sample found it in a minute.

A test that takes two minutes is telling you something

"Closing a link gives the port back" took 120 seconds because closing a listener waited out its accept timeout twice. The test was right; the duration was the finding.

An empty schema-change list is not the same as no schema changes

The release notes claimed "this is the first release" over twelve migrations, because the repository had no tags. A tool that cannot compute an answer should say so rather than print an empty one.
