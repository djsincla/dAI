Engineering · architecture

What the system is, and which part holds what

A control plane on one machine, an agent on every machine that lends capacity, and a link between machines that the control plane never touches. This describes what is built and running, not what is planned.

1

The shape of it

Three kinds of process, and a fourth that only exists during a split.

# one machine control plane Postgres, an HTTP surface, the scheduler, the console # every machine that lends capacity dai-agent work the daemon: batch loop + serving loop, one process dai-agent updater a separate launchd job, every 120s # only while a split model is answering rank 0 <-> rank 1 a direct mTLS link between two agents, port 7710

Work reaches an agent in two ways and they are not alike. Batch work is pulled: the node asks when it is ready, which suits a queue and means a machine that goes away simply stops asking. Interactive work is pushed down a reverse channel the node holds open, because a conversation cannot wait for the next poll.

The direction matters

A harvested machine dials out and never listens. Everything the control plane wants to tell a node - renew your certificate, serve this model - travels on a beat the node itself sent. There is no other way in.

Each is also separable at the listener: AGENT_PORT runs the worker API on its own port so it can be firewalled apart and kept up while the human-facing side restarts. Network ACLs run before authentication, so a request from a disallowed range is refused without touching the database.

Every group gets a further listener of its own - see tiers, groups and sockets.

3

The agent: two loops, one process

Batch and serving run side by side in one daemon because a node does both and they cannot share a loop: an interactive request must not wait for a batch unit to finish, and a batch unit must not be held behind a conversation. Keeping them in separate commands meant installing the daemon quietly turned serving off.

batch loop
Reads presence, heartbeats, leases work, syncs models and scenes, renews the certificate. It owns renewal and the model swap.
serving loop
Holds the reverse channel open, answers dispatches, and is the half that becomes a rank of a split.

They share a runtime and an identity, which is the source of a whole class of bug: anything the batch loop replaces has to be handed to the serving loop and to the three sync loops, or they go on using what was replaced. That has been wrong twice - once for a renewed certificate, once for the model sync loop - so the handover now lives in one place, in the loop that does the replacing.

Presence, and what it permits

The policy table is measured, not estimated. GPU work is forbidden wherever a user is logged in: every configuration tested was perceptible, and the gentlest - background QoS at 25% duty - still cost 46% of viewport p95.

Cluster-tier machines are exempt from presence gating for serving. The gate exists to keep work off a machine somebody is using, and a dedicated box has nobody at it; more importantly, a conversation needs a model still resident a minute from now, which the harvest tier cannot promise by design.

Known sharp edge

nodes.tier is generated as cluster if cluster is in tiers. A machine that volunteers for both reads as cluster everywhere, including for that exemption - so an interactive request can land on somebody's workstation while they are using it. The fleet view warns about it; the model has not been fixed.

5

Tiers, groups and sockets

tier
A promise a machine makes about preemption. harvest: may be taken away the moment somebody touches a keyboard. cluster: never preempted, and the only place a split can run.
group
A set of machines, the one model they serve, and a socket. A group has a tier; a machine has tiers.
socket
A port per group, allocated at creation from 8460-8499. Pointing an application at it addresses that group's machines and no others.

A machine may be in at most one group per tier. Where its cluster and harvest groups disagree about what it should serve, the cluster group wins - the two tiers are not equal claims, and only one of the two promises survives on a single machine.

The serving model is a property of the group and reaches the machine on its heartbeat; the agent swaps its runtime to match. A group can be stood down, which keeps its machines, model and socket and asserts none of them, or deleted, which takes its jobs, assignments and roles with it and retires its port.

6

A model across several machines

Pipeline parallelism: the layers are divided, and one hidden state crosses the boundary per token. How many machines is a property of the model (models.machines), declared by an operator, not inferred from how many machines a group happens to have.

# a request naming a 2-machine model, on a group's socket control plane selects a gang: all ranks or none, one group, cluster tier tells each rank: rank, size, listen or dial, port, peer, model rank 1 holds layers 0..<24, dials rank 0, sends a hidden state per token rank 0 holds layers 24..<48 plus the norm and the output head, samples the token, sends it back, and answers the request

Ranks are numbered in reverse so rank 0 owns the head and is therefore the machine that answers. Layer boundaries are accumulated rather than multiplied, because the obvious formula loses a layer whenever the count does not divide evenly - 80 layers over 3 machines drops layer 26, and a model computes happily without it.

A split runs only where an operator assigned it. The declaration is the group's serving model, so there is no second switch to keep in step and no way to declare a split for a model that is not one.

What it buys

Capacity, not speed. With one request in flight the machines run in sequence, so a 72B costs about 14% of its throughput and halves what each machine must hold - 41.10 GB on one machine against 21.31 GB on each of two. The reason to do it is that the model would not fit at all otherwise.

7

Identity

Every node has a key in the Secure Enclave and a certificate signed by the fleet's node CA. The key cannot leave the machine and cannot be used outside the daemon that created it - which is why the agent's HTTP client is NIO rather than URLSession, and why a certificate renewal can only be performed by the daemon itself.

Peer links between nodes present the same node certificate and pin the node CA - not the server CA used to reach the control plane. Pinning the wrong root fails the handshake with "unknown CA", which reads as a broken network rather than the wrong trust anchor.
